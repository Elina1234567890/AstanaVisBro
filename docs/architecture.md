# Architecture

## System overview

AstanaVis Bro is a React application hosted by the iDos Games App Shell. `src/main.tsx` creates one
`IDosGamesClient`, then mounts the base module followed by the active modules from `src/modules.ts`.

```text
index.html
  └─ src/main.tsx
       ├─ src/config.ts + src/idos.title.ts
       ├─ src/ui.config.ts
       └─ mountHost({ client, modules })
            ├─ src/base/
            └─ src/modules/*
```

## Runtime responsibilities

### Base module

`src/base/` owns sign-in, access checks, the lobby, account controls and the frame around in-lobby
content. It also provides shared UI roles such as currency, wallet and menu presentation.

### Active platform modules

The active composition in `src/modules.ts` currently includes:

- `profile` — account and client preferences;
- `store` — the server-resolved storefront;
- `collections` — card sets, packs, chests and trades.

These modules use the shared SDK client and the iDos Games Title configuration. Store offers,
currencies, cards and other backend entities are configured on the platform, not in this repository.

### Game routes

`orb-merge`, `color-flow` and `cake-sort` each register a separate route through
`ctx.registerRoute`. At this stage they render responsive DOM stage panels and explicitly expose
`implemented: false` to the platform agent bridge.

### Communication boundaries

Modules do not import one another. Cross-module navigation uses registered features and routes;
live communication uses typed platform events. Shared pure code may live in `src/shared/` when two
or more modules need it.

## Configuration

- `src/app.config.ts` selects the initial route and lobby order.
- `src/ui.config.ts` owns the global theme, motion and sound settings.
- `src/modules.ts` is the source of truth for active modules and is regenerated by the platform.
- `src/idos.title.ts` is generated identity metadata and must not be edited manually.
- `src/config.ts` resolves Title identity and environment and is platform-owned.
- `.env.local` is optional and local-only; see `.env.example` for supported values.

## Build and quality

Vite produces the browser bundle. TypeScript runs in strict mode. GitHub Actions performs a clean
`npm ci`, type-check and production build for each pull request and each push to `main`.

## Security model

The application is client-side. Secrets, service credentials and private keys must never be added
to source or Vite environment variables. Authoritative rewards, inventory, economy and eligibility
belong to the iDos Games backend and Title configuration.
